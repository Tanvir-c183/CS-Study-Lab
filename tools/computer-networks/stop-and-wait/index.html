Theoretical Protocol Manual

Stop-and-Wait ARQ Formal Specification & Performance Model

Comprehensive mathematical derivations, Finite State Machine (FSM) transitions, and efficiency bounds for Stop-and-Wait ARQ.

Stop-and-Wait Mathematical Formulas

Stop-and-Wait Efficiency (\eta)
\eta = \frac{T_t}{T_t + 2T_p} = \frac{1}{1 + 2a}
Derived where a = T_p / T_t. Assumes zero ACK transmission time and error-free channel.
1-Bit Sequence Space (M = 2)
S \in \{0, 1\}, \quad ACK \in \{0, 1\}
A single bit sequence number is necessary and sufficient to prevent duplicate packet confusion caused by lost ACKs.
Effective Throughput (S)
Throughput = \eta \times Bandwidth
Actual useful data rate delivered across the link.

Sender Finite State Machine (FSM)

State 1: Ready / Idle State

Awaiting packet request from network layer. Assigns current sequence bit S_{next} \in \{0,1\}, sends frame F_{S_{next}}, and starts timer.

State 2: Blocking Wait State

Cannot accept new network packets until current frame is ACKed.
• On Matching ACK: Stop timer, flip sequence bit S_{next} \leftarrow 1 - S_{next}, return to Ready State.
• On Timeout / Corrupt ACK: Retransmit F_{S_{next}}, restart timer.

Receiver Finite State Machine (FSM)

Expecting Frame R_{next} \in \{0, 1\}

Receiver listens continuously for incoming data frames.

Handling Arrival Events

• Valid Frame F_{R_{next}} Arrives: Deliver payload to application layer, update R_{next} \leftarrow 1 - R_{next}, send ACK_{R_{next}}.
• Duplicate Frame Arrives (Old S): Discard payload (duplicate), re-send ACK expecting R_{next}.
• Corrupted Frame: Discard frame completely; take no action (sender timer will expire).

Stop-and-Wait Efficiency (\eta) vs Ratio a = T_p / T_t

Stop-and-Wait Limitations:

  • • Low Link Utilization: When propagation delay (T_p) is high compared to frame transmission time (T_t), efficiency drops rapidly toward zero.
  • • High Delay-Bandwidth Products: For long-haul links or satellite links (a \gg 1), Stop-and-Wait spends almost all its time waiting for ACKs.
  • • Optimal Condition: Stop-and-Wait is efficient (\eta > 50\%) only when a < 0.5 (short physical distance or very low bandwidth).

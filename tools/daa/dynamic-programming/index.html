Understanding Dynamic Programming

Dynamic Programming (DP) is an algorithmic paradigm that solves complex problems by breaking them down into simpler subproblems, solving each subproblem exactly once, and storing its answer in a table to avoid redundant computations.

1. Optimal Substructure

A problem exhibits optimal substructure if an optimal solution to the overall instance is constructed directly from optimal solutions to its constituent subproblems.

2. Overlapping Subproblems

A problem has overlapping subproblems if a standard recursive decomposition evaluates the exact same subproblem instances repeatedly.

Core Transformation Pipeline
Naive Recursion → Repeated Subproblems → Memoization / Tabulation → Optimal Subproblem Table

Memoization vs. Tabulation Comparison

Feature Memoization (Top-Down) Tabulation (Bottom-Up)
Approach Strategy Starts from target main problem and recursively breaks down to base cases. Starts from primitive base cases and iteratively fills table up to target state.
Call-Stack Overhead Incurs function recursion stack overhead; risk of call-stack overflow. Zero recursion stack overhead; executes strictly via iterative loops.
Subproblem Evaluation Evaluates subproblems lazily (only calculates required states). Evaluates subproblems eagerly (systematically computes all table entries).
Exam Recommendation Used primarily in recursive conceptual proofs. Standard for RBU exam numericals & table construction!
Top-Down Memoization uses a lookup array initialized with sentinel values (-1) to cache recursive results on-demand.

Greedy Paradigm vs. Dynamic Programming

Greedy Strategy Failure Case

Dijkstra's greedy algorithm permanently locks vertex distances upon extraction from priority queue. When negative edge weights exist, a later path could reduce cost, causing Dijkstra to fail.

Dynamic Programming Advantage

Bellman-Ford re-evaluates all edges over V-1 relaxation passes, guaranteeing optimal path distance recovery even in the presence of negative edge weights.
